- **Agents — Activation et désactivation d'un agent** : nouvel endpoint `PATCH /api/agents/{id}` pour changer le drapeau `active` d'un agent existant, seule modification possible après sa création ; chaque changement est journalisé.
  - `PATCH /api/agents/{id}` (route `agent_active`, `id` numérique) reçoit un objet JSON `{"active": bool}` avec `Content-Type: application/json` et renvoie `200` avec l'objet agent complet `{"id", "name", "email", "active"}` (clés dans cet ordre, aucune autre clé) après modification. `name` et `email` ne sont jamais modifiés par cet endpoint ; les clés inconnues du corps (`name`, `email`, `id` compris) sont ignorées. Envoyer la valeur déjà en place est accepté (`200`, même corps).
  - La valeur est persistée : `GET /api/agents` reflète immédiatement le nouveau drapeau et son tri (actifs d'abord, puis `id` croissant). Désactiver un agent ne retire pas ses affectations : les tickets qui lui sont affectés le restent.
  - Validation (`422`, `application/json`, corps `{"errors": {"active": "<message>"}}`, `active` seule clé de `errors`) : clé `active` absente (`{}` ou autres clés seulement), `null`, chaîne (`"yes"`, `"true"`, `""`), nombre (`1`, `0`) ou tableau. L'agent n'est pas modifié dans ces cas. Le corps est validé avant la recherche de l'agent : un `id` inconnu avec un corps invalide renvoie `422`, pas `404`.
  - `id` numérique sans agent correspondant : `404` avec exactement `{"error": "Agent not found"}`. `id` non numérique (`/api/agents/abc`) : `404` `{"error": "<message>"}` (requirement `\d+` de la route). `GET /api/agents/{id}` : `405` `{"error": "<message>"}` avec un en-tête `Allow` contenant `PATCH`. Corps non JSON ou vide : `400` ; `Content-Type` autre que JSON : `415` (`#[MapRequestPayload(acceptFormat: 'json')]`). Toutes ces erreurs sont en `application/json`, rendues par `ApiExceptionListener` existant.
  - Journalisation : chaque `200` (y compris sans changement de valeur) écrit, après le `flush()`, exactement une ligne `info` `Agent activation changed` avec le contexte `{"id": <id agent>, "active": <nouvelle valeur>}` ; les réponses `400`, `404`, `415` et `422` ne sont pas journalisées.
  - Nouveau fichier `src/Dto/UpdateAgentActiveRequest.php` (DTO `final readonly`, propriété `?bool $active = null` avec `#[Assert\NotNull]` ; la valeur par défaut `null` fait qu'une clé manquante est refusée au lieu d'activer silencieusement l'agent) ; `AgentController` gagne l'action `changeActive()`, ses actions `list` et `create` et son constructeur sont inchangés. Aucune migration, aucun changement de schéma, aucune dépendance ni configuration ajoutée ; `Agent`, `AgentRepository`, `ApiExceptionListener` et `TicketController` ne sont pas modifiés.
  - Appelants existants : `GET /api/agents`, `POST /api/agents` (y compris ses corps `422` et le message d'e-mail en doublon), `GET/POST /api/tickets`, `GET /api/tickets/{id}`, `PATCH /api/tickets/{id}/status` et `GET /api/stats` conservent leurs codes de statut et leurs corps JSON.
  - **Impact API** : nouvelle route `PATCH /api/agents/{id}` (`200`, `400`, `404`, `415`, `422`) et, par conséquent, `405` au lieu de `404` pour les autres méthodes sur `/api/agents/{id}` numérique. Aucune clé ajoutée, renommée ou supprimée sur l'objet agent, aucun code de statut existant modifié.
